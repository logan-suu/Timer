# 秋招日程云端源码

沿用根目录的界面和时区逻辑，使用 Sites 私人站点、ChatGPT 登录与 Cloudflare D1 持久保存。部署后，手机和电脑可共用日程；电脑无需一直开机。需要联网。

公开源码不提供共享的线上服务，不包含作者的站点身份、网址、凭据或数据。请创建自己的私人站点和数据库。

## 配置

需要 Node.js 22.13 或更新版本。先从示例创建本机配置：

```sh
cd cloud
cp .openai/hosting.example.json .openai/hosting.json
npm ci
```

示例仅声明 D1 绑定 `DB`，未绑定任何既有站点。使用 Sites 部署时，为你自己的站点设置 `project_id`，保留 D1 绑定并应用 `drizzle/0000_wet_psylocke.sql` 中的表结构。实际 `.openai/hosting.json`、本机数据库和运行配置均被 Git 忽略。

框架命令：

```sh
npm run dev -- --port 5174 --hostname 127.0.0.1
npm run build
```

本机预览使用模拟登录身份，数据库也需要先初始化。线上身份验证依赖 Sites 的受保护入口，请通过 Sites 的部署流程发布。

## 维护界面

在仓库根目录维护 `src/`、`shared/` 和 `public/`，然后同步到本目录：

```sh
node cloud/scripts/sync-local-ui.mjs
```

之后在 `cloud/` 中进行类型检查、构建和预览。已有部署应复用自己的站点 ID，按 Sites 工作流更新。推送 GitHub 本身不会自动部署站点。

显示、对照和通知录入均支持全球城市时区；新用户默认使用设备时区，旧设置和实际日程时刻保持不变。

## 数据与访问

当前实现面向单人使用：每个私人站点保存一份日程。`/api/schedule` 要求已登录身份；`/api/initial-import` 是一次性导入接口，依赖站点所有者的私人访问边界，只在尚无数据时插入。**不要把此实现部署为允许其他人访问的共享站点**；多用户版本需要增加按用户隔离的数据授权。

数据库保存当前日程、版本号及上一版备份。保存以原子语句检查版本，避免旧设备覆盖新修改。未编辑时每 15 秒检查其他设备更新，回到网页时也会检查；编辑中的草稿不会被后台读取替换。

本地文件版的 `.data/` 与云端数据库相互独立，需要时自行导出和导入备份。源码、迁移文件和 Git 历史中均不包含个人日程。
